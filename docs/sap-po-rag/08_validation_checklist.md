# 구매오더 생성 전 검증 체크리스트

에이전트는 PO를 만들기 전에 아래 항목을 **순서대로** 확인합니다. 하나라도 실패하면 생성하지 말고 사용자에게 이유를 알립니다.

## 1. 요청 완결성

- [ ] 품목(자재번호 또는 품목 텍스트+자재그룹)
- [ ] 수량과 단위
- [ ] 납품 희망일(오늘 이후)
- [ ] 받을 플랜트(와 저장위치)
- [ ] 비재고 구매라면 비용 귀속처(비용센터/WBS/내부오더/자산)
- [ ] 공급업체(없으면 소스 리스트·정보레코드로 후보 제안)

빠진 값은 `00_company_config_template.md`의 기본값으로 채울 수 있는 것만 채우고, 나머지는 사용자에게 묻습니다.

## 2. 마스터 데이터

- [ ] 공급업체가 존재하고, 구매조직으로 확장돼 있고, 구매 블록이 없다
- [ ] 자재가 해당 플랜트에 확장돼 있고 구매 가능한 상태다
- [ ] 소스 리스트가 필수인 자재라면 공급업체가 목록에 있다
- [ ] 구매조직이 플랜트를 담당한다

## 3. 참조 문서 우선 확인

- [ ] 요청에 해당하는 **승인된 구매요청(PR)** 이 있는가 → 있으면 PR 참조
- [ ] 공급업체-자재 **계약**이 유효한가 → 있으면 계약 참조
- [ ] 없으면 직접 생성

## 4. 가격

- [ ] 정보레코드/계약 단가가 있으면 그 값을 쓴다
- [ ] 사용자가 말한 단가가 정보레코드 단가와 **±10% 이상** 차이 나면 확인을 받는다(비율은 회사 정책에 맞게 조정)
- [ ] 단가 0 또는 음수 금지
- [ ] 통화가 공급업체 주문 통화와 같다

## 5. 중복 발주

- [ ] 최근 `<7>`일 안에 같은 공급업체·자재·플랜트로 만든 PO가 있는지 조회(OData `$filter` 또는 `ME2L`/`ME2M`)
- [ ] 같은 요청 ID(`OUR_REF` / `CorrespncInternalReference`)로 이미 만든 PO가 있는지 조회. 있으면 **새로 만들지 말고 기존 PO 번호를 알려 줌**(재시도 시 중복 생성 방지)

## 6. 금액·승인

- [ ] 총액 = Σ(수량 × 단가 ÷ 가격단위)을 계산한다
- [ ] `00_company_config_template.md`의 승인 한도와 비교해 에이전트가 생성해도 되는 금액인지 확인
- [ ] 예산 통제 대상(비용센터·WBS)이면 가용 예산 초과 경고에 주의

## 7. 시뮬레이션

- [ ] BAPI면 `TESTRUN='X'` 결과에 오류(`E`/`A`) 없음
- [ ] OData면 QAS에서 같은 형태의 요청이 성공한 이력이 있음

## 8. 사용자 확인

- [ ] 요약(공급업체, 품목, 수량, 단가, 총액, 납기, 비용 귀속처, 경고)을 보여 주고 명시적 "승인/진행" 답을 받음
