# MM 조직 구조와 마스터 데이터

## 조직 구조

| 조직 단위 | 영문 | 설명 |
|---|---|---|
| 회사코드 | Company Code | 독립된 회계 단위. PO 헤더에 들어감 |
| 구매조직 | Purchasing Organization | 벤더와 조건을 협상하는 단위. 벤더는 구매조직별로 확장돼 있어야 함 |
| 구매그룹 | Purchasing Group | 구매 담당자(또는 담당 팀) 코드 |
| 플랜트 | Plant | 자재를 받는 공장·사업장. 품목 단위로 지정 |
| 저장위치 | Storage Location | 플랜트 안의 창고. 재고 자재 입고 시 사용 |

관계: 회사코드 1 : N 플랜트, 구매조직은 하나 이상의 플랜트를 담당하도록 할당됩니다. **PO의 구매조직이 품목 플랜트를 담당하지 않으면 오류가 납니다.**

## 공급업체(벤더) 마스터

| 확인 항목 | 이유 | 조회 |
|---|---|---|
| 벤더 번호 존재 | 없는 번호는 PO 불가 | S/4: `BP` / ECC: `XK03`, `MK03` |
| 구매조직 확장 여부 | 해당 구매조직 데이터가 없으면 PO 불가 | 위와 같음(구매조직 뷰) |
| 구매 블록/삭제 표시 | 블록된 벤더는 PO 불가 | 위와 같음 |
| 주문 통화, 지급조건 | PO 헤더 기본값으로 들어감 | 위와 같음 |

S/4HANA에서는 벤더가 비즈니스 파트너(BP)로 통합돼 "Supplier"라고 부릅니다. BP 번호와 Supplier 번호가 다를 수 있으니 PO에는 **Supplier 번호**를 씁니다.

## 자재 마스터

| 확인 항목 | 이유 | 조회 |
|---|---|---|
| 해당 플랜트에 자재 확장 여부 | 플랜트 뷰가 없으면 PO 불가 | `MM03` |
| 구매 뷰 존재 | 구매그룹, 주문단위 등 | `MM03` |
| 기본단위 / 주문단위 | 수량 단위 변환 | `MM03` |
| 자재 상태(블록) | 구매 금지 상태 확인 | `MM03` |
| 자재그룹 | 자재번호 없는 품목에 필수 | `MM03` |

자재번호 없이 텍스트로 발주하는 경우(비재고 구매)에는 **품목 텍스트, 자재그룹, 계정지정범주**가 필수입니다.

## 구매정보레코드(Info Record)

벤더-자재(-구매조직-플랜트) 조합의 단가, 납기, 주문단위를 저장합니다.

- 조회: `ME13` / 생성: `ME11` / 변경: `ME12`
- PO 생성 시 단가가 자동 제안됩니다. 에이전트는 **정보레코드 단가를 우선** 쓰고, 사용자가 다른 단가를 말하면 차이를 알려 줍니다.

## 소스 리스트(Source List)

자재별로 허용된 공급업체와 유효기간을 정합니다.

- 조회: `ME03` / 유지: `ME01`
- 플랜트에서 소스 리스트가 필수로 설정돼 있으면 목록에 없는 벤더로는 PO를 만들 수 없습니다.

## 계약

- 수량/금액 계약: `ME31K` 생성, `ME33K` 조회
- 일정계약: `ME31L` 생성, `ME33L` 조회
- 계약이 있으면 PO에서 계약 번호(`Agreement`/`AGREEMENT`)와 품목(`AgreementItem`/`AGMT_ITEM`)을 참조합니다.
