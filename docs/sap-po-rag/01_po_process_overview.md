# SAP MM 구매 프로세스 개요

## 전체 흐름

```
구매요청(PR) → [견적요청(RFQ)/견적] → 구매오더(PO) → 승인(Release)
→ 공급업체 전송 → 입고(GR) → 송장검증(IV) → 대금 지급(FI)
```

| 단계 | 문서 | 대표 T-code | 담당 |
|---|---|---|---|
| 1. 구매요청 | Purchase Requisition | `ME51N` 생성 / `ME53N` 조회 | 요청 부서 |
| 2. 견적(선택) | RFQ / Quotation | `ME41` / `ME47` / `ME49` | 구매 |
| 3. 구매오더 | Purchase Order | `ME21N` 생성 / `ME22N` 변경 / `ME23N` 조회 | 구매 |
| 4. 승인 | Release | `ME29N` 개별 / `ME28` 일괄 | 승인권자 |
| 5. 입고 | Goods Receipt | `MIGO` (이동유형 101) | 창고 |
| 6. 송장검증 | Invoice Receipt | `MIRO` | 회계 |
| 7. 지급 | Payment | `F110` | 회계 |

## 발주 에이전트의 범위

에이전트가 맡는 부분은 **3단계(PO 생성)** 이고, 1단계(PR 조회·참조)와 PO 조회까지만 보조합니다.

- 할 수 있는 일: 요청 해석, 마스터 데이터 조회, PO 초안 작성, 시뮬레이션(테스트 실행), 사용자 확인 후 생성, 생성 결과 보고
- 하면 안 되는 일: 승인(Release), 입고, 송장 처리, 마스터 데이터 변경(`10_agent_policy_guardrails.md` 참고)

## PO를 만드는 세 가지 방법

1. **PR 참조 생성**: 승인된 구매요청이 있으면 PR 번호·품목을 참조해 PO를 만듭니다. 가격·수량·계정지정이 PR에서 넘어오므로 가장 안전합니다.
2. **계약 참조 생성**: 벤더와 계약(`ME31K`)이나 일정계약(`ME31L`)이 있으면 계약 번호를 참조합니다. 계약 단가가 적용됩니다.
3. **직접 생성**: 참조 없이 벤더·자재·수량·가격을 직접 입력합니다. 가격은 구매정보레코드(Info Record)가 있으면 자동으로 제안됩니다.

에이전트는 **1 → 2 → 3 순서로 우선 검토**합니다. 참조 문서가 있으면 직접 생성보다 참조 생성을 택합니다.

## PO가 만들어진 뒤

- 승인 전략이 걸린 PO는 승인되기 전까지 공급업체에 출력·전송되지 않고, 입고도 할 수 없습니다.
- 승인 상태는 `ME23N` 헤더의 "Release strategy" 탭에서 확인합니다.
- 공급업체 전송(출력)은 메시지 유형(예: `NEU`) 설정에 따라 자동 또는 수동으로 나갑니다.
